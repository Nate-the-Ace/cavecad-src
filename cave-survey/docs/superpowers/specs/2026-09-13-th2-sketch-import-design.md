# Therion `.th2` sketch import

A TopoDroid or Therion survey arrives as numbers *and* a drawing. The `.th`
reader takes the numbers and `CsTherion.js` says plainly that it skips
`scrap`/`endscrap`. So a caver who sketched the whole cave on a phone
imports a bare centreline and then re-traces, by hand, a photograph of a
sketch they already drew in vector.

This takes the drawing half too.

## What an imported scrap IS

**Real map ink.** Scrap lines, areas and points become ordinary CaveCAD
entities on the ordinary feature layers, tagged the way Feature Trace and
the Symbol Palette tag their own output: editable, counted by Build Legend
and Check Map, plotted on a sheet, regenerated by the shaped-line and area
listeners. The phone sketch is the map's first draft, not a tracing
reference. (Sketch Scans keeps rasters; this is not that.)

## Architecture

Five Core files plus one hook. Nothing in the parser knows about the
document; nothing in the drawing knows about Therion's vocabulary.

| File | Job | Document? |
| --- | --- | --- |
| `Core/Format/CsTherion2.js` | `.th2` text to a neutral sketch model | no — node-testable |
| `Core/CsSketch.js` | the mapping table: th2 vocabulary to layer / symbol / shaped-line / area | no |
| `Core/CsSketchPlace.js` | station pairs to a fit matrix, then MLS control pairs | no |
| `Core/CsSketchDraw.js` | model + placement to tagged entities | yes |
| `Core/CsSketchStore.js` | scrap identity, what is already imported | yes |

`CsTherion2` is **not** registered in `CsRegistry`: the registry answers
"which survey reader claims this file", and a `.th2` carries no centreline
at all. It is reached from `ImportCaveSurvey` after the `.th` is read.

### The model

```
{ scraps: [ {
    name, projection: "plan"|"extended"|"elevation"|"none",
    projectionAngle,                   // elevation only
    scale: {unitsPerDrawing} | null,   // from -scale [...]
    stations: [ {name, x, y} ],
    lines:  [ {type, subtype, closed, reversed, id,
               segs: [ {to:[x,y], c1:[x,y]|null, c2:[x,y]|null} ] } ],
    areas:  [ {type, lineIds:[...]} ],
    points: [ {type, x, y, orientation, scale, text} ],
    texts:  [ {x, y, text, orientation} ]
  } ],
  findings: [ ... ] }
```

Bezier stays Bezier through the parse. th2 line segments are cubic;
flattening them at read time throws the curve away before anyone can
decide how to draw it. `CsSketchDraw` writes a spline from the control
points — it does **not** push the path through `CsTrace.resample`, which
exists to tame a freehand drag and would only coarsen a vector sketch.

### Refusals and findings

Refused outright, through `CsModel.addParseFinding` (the channel every
import report already prints):

* `input` — a split Therion project. Same reason the `.th` reader refuses
  it: a cave silently missing half its passages is the worst failure a
  reader can have.
* `##XTHERION## xth_me_image_insert` — a raster underlay. Sketch Scans
  owns rasters.
* `-projection elevation` — a *projected* elevation is not an extended
  one. Bending it along the developed axis would be wrong in a way that
  looks right.

Reported but not refused: unknown `line`/`point`/`area` types, which land
on a catch-all layer. Therion's vocabulary grows, and a sketch missing its
walls is worse than one with a stray line on `NOTES-ANNOTATION`.

## The mapping

Three dicts in `CsSketch.js`, shaped like `CsSymbols.CATALOG` and
`CsArea.CATALOG` so they read like the rest of the suite. The rows that
carry a decision:

| th2 | becomes |
| --- | --- |
| `line wall` | `WALLS-SURVEYED`; `-subtype presumed` to `WALLS-INFERRED`; `invisible` not drawn, counted |
| `line pit` `slope` `floor-step` `ceiling-step` `flowstone` | shaped lines `pte` `slp` `lgf` `lgc` `fst` — spine written, `CsShapeLine` generates the ornament |
| `line border` | consumed by its `area`, else `CTRL-AREA-BOUNDARY` |
| `line survey` | dropped, counted — the `.th` already brought the centreline |
| `area water` `sump` `sand` `clay` `pebbles` `debris` `blocks` `flowstone` `moonmilk` `ice` `bedrock` | `CsArea.CATALOG` keys, near 1:1 — the thirteen shipped patterns *are* the Therion vocabulary |
| `point stalactite` `stalagmite` `pillar` `curtain` `guano` `entrance` `sump` `spring` ... | `CsSymbols.CATALOG` blocks; `-orientation` to angle, `-scale xs..xl` to size |
| `point station` | **not drawn** — it is a tie point; the drawing letters its own stations |
| `point altitude` | a Callout carrying the floor elevation (`CsCallout` already reads exactly this) |
| `point label` / `remark` / `name` | `TEXT-LABELS` / `NOTES-ANNOTATION` / `NOTES-NAME` |
| `point continuation` | `NOTES-DIG`, plus a finding naming it — this is a **lead**, and leads have no home yet |
| `u:<anything>` | catch-all layer, plus a finding |

Rimstone goes one way only: the suite has `rst`, Therion has no line
equivalent.

## Placement

Tie pairs are `(scrap xy, drawing xy)` per `point station`.
`CsScanFit.fit` first, then `CsWarp.mlsSimilarity` per vertex against the
same pairs — Bezier control points warped alongside their anchors, so a
curve stays a curve. This is what Therion itself does, and it absorbs
loop-closure adjustment for free.

**The residual report quotes the PRE-warp figure.** Post-warp residuals
are zero by construction, so reporting them would say "perfect fit" about
every scrap ever imported — the same lie as quoting post-adjustment loop
closure as a grade.

Station count decides what is possible:

| Stations | Fit | Warp |
| --- | --- | --- |
| 3 or more | affine | yes |
| 2 | similarity | yes |
| 1 | translation at the scrap's own `-scale` | impossible, and said so |
| 0 | refused (plan and extended) | — |

Per projection:

* **plan** — the plan frame.
* **extended** — the run is whichever profile band holds the majority of
  its stations (`CsProfileBox.boxes`, `runForPath`); targets come from
  `CsDrape.placeBand`, so scrap x is developed distance and scrap y is
  elevation. Draws to `PROFILE-*` layers, shaped lines via
  `CsShapeLine.PROFILE_TWIN`.
* **`none`** (cross section) — a section bay at the station the plan
  scrap's `point section -scrap <name>` refers to. These carry no station
  points, so placement is scale-only via `CsSectionBay.calibrationFrom`:
  rigid, never warped, and the report says which sections came in
  unwarped.

## The door

`Import Cave Survey` reads the `.th` as it does now; if sibling `.th2`
files sit beside it — or a `.thconfig` names them — it says so and imports
the drawing half in the same pass. A TopoDroid export folder comes in
whole, in one gesture. A `.th2` picked directly is the same path with no
centreline step.

## Re-import

Every entity carries its scrap id and its th2 object index. A second
import of a scrap already present **refuses and asks**, per scrap: replace
it, or skip it. No silent overwrite — the ink is real, editable, and a
caver will have worked on it.

`CsBackup` takes its usual snapshot before any replace, so the answer to a
wrong choice is the folder.

## Tests

`testdata/PitfallCave.th` plus `PitfallCave.th2` (plan, extended and one
section scrap), written against the existing Pitfall Cave fixture so the
station names tie to a survey the harness already knows.

Unit coverage in `tests/js_unit.js`, run under node and `qcad -no-gui`:
parser (every supported construct, each refusal, Bezier round-trip), the
mapping dicts (every catalog key they name must exist in `CsLayers`,
`CsSymbols.CATALOG`, `CsArea.CATALOG` or `CsShapeLine.STYLES` — the same
discipline the template/registry agreement test uses), and placement
(known transform in, residuals out; warp exact at its control points).

New files must be added to **both** `Core/CsAll.js` and the hand-written
list in `tests/js_unit.js`: a Core file missing from that list passes
silently through the harness's deliberate catches.

A handbook page ships with the feature; the suite's tests fail on an
undocumented tool.

## Phases

1. `CsTherion2.js` + fixture + parser tests.
2. `CsSketch.js` mapping + catalog-agreement tests.
3. `CsSketchPlace.js` + placement tests.
4. `CsSketchDraw.js` / `CsSketchStore.js`, plan projection only, drawn live.
5. Extended and section projections.
6. `ImportCaveSurvey` hook, re-import dialog, handbook page.
